# กติกาทางธุรกิจ (Business Rules)

อ้างอิงโจทย์: ตารางสรุปเป็นรายหมวดหมู่ย่อยภายใต้หมวดหมู่ พร้อมข้อมูลฝั่งซื้อ ฝั่งขาย และคงเหลือ

## ข้อมูลในตาราง

| ส่วน | คอลัมน์ | มาจาก |
|---|---|---|
| **ซื้อ** | จำนวนรวม (กก.) | ผลรวม `quantityKg` ของบรรทัด `tradeType = buy` |
| | ราคา (บาท/กก.) | ช่วง ต่ำสุด–สูงสุดของ `pricePerKg` (ถ้ามีราคาเดียว แสดงตัวเดียว) |
| | จำนวนแยกเกรด A/B/C/D | ผลรวม `quantityKg` แยกตาม `grade` |
| | เลขออเดอร์ | `orderId` ที่เกี่ยวข้อง (ไม่ซ้ำ เรียงตามตัวอักษร) |
| | ยอดรวม (บาท) | ผลรวม `amountBaht` |
| **ขาย** | (เหมือนฝั่งซื้อ ทุกข้อ แต่ใช้ `tradeType = sell`) | |
| **คงเหลือ** | จำนวนคงเหลือ (กก.) | **จำนวนซื้อรวม − จำนวนขายรวม** |
| | เงินคงเหลือ (บาท) | **ยอดรวมซื้อ − ยอดรวมขาย** |

แถวระดับหมวดหมู่ = ผลรวมของหมวดย่อยทั้งหมดที่ผ่าน filter (ราคา = ต่ำสุด/สูงสุดของทั้งหมวด)
แถว "รวมทั้งหมด" ท้ายตาราง = ผลรวมทุกหมวด

คงเหลืออาจติดลบได้ (ขายมากกว่าซื้อในข้อมูลที่ผ่าน filter) — ระบบแสดงตามจริง ไม่ปรับเป็น 0

## ตัวกรอง (Filters)

ทุกตัวเป็น optional และ **ใช้ร่วมกันแบบ AND**

| Filter | Query param | กติกา |
|---|---|---|
| วันที่ | `dateFrom`, `dateTo` (`YYYY-MM-DD`) | ใช้ฟิลด์ `orderFinishedDate`, **รวมวันเริ่มและวันสิ้นสุด**, ใส่ด้านเดียวได้ |
| หมวดหมู่ | `categoryId` | เท่ากับ |
| หมวดหมู่ย่อย | `subCategoryId` | เท่ากับ; หน้าเว็บให้เลือกได้เฉพาะหมวดย่อยของหมวดที่เลือก |
| เลขออเดอร์ | `orderId` + `orderIdMode` | `exact` (ค่าเริ่มต้น) = ตรงทั้งหมด, `contains` = มีข้อความนี้ (ไม่สนตัวพิมพ์เล็กใหญ่) |
| ช่วงราคา | `priceMin`, `priceMax` | เทียบกับ **ราคาต่อ กก. ของแต่ละบรรทัด** (รวมค่าขอบ) |
| เกรด | `grade` (เช่น `A,B`) | เลือกได้หลายเกรด |

### การทำงานของ filter กับยอดสรุป

Filter ทำงานที่ระดับ **บรรทัดสินค้า** (1 บรรทัด = ออเดอร์ × หมวดย่อย × เกรด) *ก่อน* รวมยอด จึงได้ผลตามที่โจทย์ต้องการโดยธรรมชาติ:

- เลือกเกรด `A` → จำนวน/ยอดเงินรวมเฉพาะเกรด A, คอลัมน์เกรดอื่นเป็น 0, หมวดย่อยที่ไม่มีเกรด A **ไม่แสดง**
- เลือกช่วงราคา → รวมเฉพาะบรรทัดที่ราคาอยู่ในช่วง และช่วงราคาที่แสดงก็มาจากบรรทัดเหล่านั้น
- ค้นเลขออเดอร์ → แสดงเฉพาะหมวดย่อยที่ออเดอร์นั้นมี และรวมเฉพาะบรรทัดของออเดอร์นั้น
- เลือกวัน → นับเฉพาะออเดอร์ที่ `orderFinishedDate` อยู่ในช่วง ทั้งฝั่งซื้อและขาย (คงเหลือจึงเป็นของช่วงนั้น ไม่ใช่ยอดสะสมตั้งแต่ต้น)

## ข้อตกลงเรื่องข้อมูลต้นทาง (ที่ตัดสินใจไว้)

| เรื่อง | สิ่งที่พบ | การตัดสินใจ |
|---|---|---|
| `quantity` | ต้นทางเป็น string (บางรายการเป็นทศนิยม) | แปลงเป็น number ตอน sync |
| เกรดที่ไม่มีของ | quantity = 0 | ไม่เก็บลง DB |
| `total` | **ไม่เท่ากับ `price × quantity` เสมอไป** ในข้อมูลตัวอย่าง (พบหลายรายการ) | เก็บ `total` ตามต้นทางเป็น `amountBaht` ไม่คำนวณใหม่ |
| วันที่ | `YYYY-MM-DD` ไม่มี timezone | เก็บเป็น 00:00 UTC; ไม่ใช้ `orderFinishedTime` |
| `transactionParties`, `stability` | ไม่ได้ใช้ในโจทย์ | ไม่เก็บ (ถ้าต้องการในอนาคต ให้เพิ่มใน `normalizeOrders`) |
| ราคา = 0 แต่มีจำนวน | พบ 23 บรรทัดในข้อมูลตัวอย่าง (ราคา 0 แต่ quantity > 0) | เก็บและนับตามจริง จึงเห็นช่วงราคาขึ้นต้นด้วย 0 ได้ (เช่น "0–66") |
| เลขออเดอร์ซ้ำ | ไม่พบเลขออเดอร์ซ้ำ ทั้งในและระหว่างซื้อ/ขาย | key `(orderId, tradeType, subCategoryId, grade)` |
| การปัดเศษ | ผลรวมทศนิยมอาจคลาดเคลื่อน | ปัด 2 ตำแหน่งตอนส่งออก |
